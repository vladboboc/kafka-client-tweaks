# Recipes · the code to copy

Every chapter has a demo, and the demo is mostly measurement: seeding topics, timing, reading metrics, printing
tables. The part worth copying into your own service is small, and it lives in its own files:

- **Code in a `recipe` package is the tweak. Everything else measures it.** Each demo calls its recipe, so the
  numbers in the chapter are the recipe's numbers.
- **Plain-client recipes** (`plain-clients/.../producer/recipe`, `consumer/recipe`, `avro/recipe`) import only the JDK,
  `org.apache.kafka.*` and `io.confluent.*`: copy a file and it compiles. Configuration recipes return a
  `Map<String, Object>` of settings for `props.putAll(...)`, one comment per setting (why, the default, the price);
  behaviour recipes (poll loops, rebalance listeners, the exactly-once loop) are small classes with a `pollOnce`.
- **Spring recipes** (`spring-boot-kafka/.../<chapter>/recipe`) are the configuration classes, container factories
  and listeners. Where a listener body calls `probe.*`, `script.*` or an injected `OrderHandler`, that is the demo's
  instrumentation or scripted failure: your processing goes there.
- Each chapter shows its recipe in a **"The code that matters"** section. Those snippets are verbatim excerpts, and
  `DocSnippetsTest` fails the build when one of them no longer matches its file.
